# Decisions

A short log of settled decisions. Newest at the bottom. Format: date, decision, why.

1. **2026-11-07: Switch on Fire TV ruled out.** Fire TV has a 32-bit userspace, 1–2 GB RAM and mobile GPUs. TVPort's approach of running native arm64 code is impossible here.
2. **2026-11-07: Directions: N64 static recompilation and native games on Vega OS** (user's choice).
3. **2026-11-07: No commercial cartridges for now.** N64 work targets freely licensed libdragon homebrew (libdragon examples, N64brew Jam 2024). Commercial recomps are deferred (user is US-based; cartridges aren't at hand).
4. **2026-11-07: Vega rendering is OpenGL ES only.** `createGpuDeviceUsingVulkanApi` always throws. RT64 is unusable on Vega, so N64 work needs a GLES renderer.
5. **2026-11-07: Pure native app model.** An `IInteractiveComponent` plus a factory exported as `<pkg-id>.entry_point_factory`, with no React Native. This is documented in the SDK's `application-overview.md`.
6. **2026-11-07: Build via `vega build` with a minimal `package.json` (`projectType: native`)**, not hand-rolled toolchain flags. The SDK toolchain needs about a dozen internal variables that `vega build` sets.
7. **2026-11-07: No Amazon template or SDK code in the repo.** It's proprietary. All app code is original. The license for our code is MIT (see #13).
8. **2026-11-07: Builder Tools MCP installed in agent mode (opt-in `adbt-dev`)**, not as an always-on steering doc. Its guidance is React Native-centric and would be noise for native work.
9. **2026-11-07: Fire Max 11 tablet is an optional bench device, not the target.** The headline is Fire TV.
10. **2026-11-07: User granted commit permission for this repo.** Pushing still needs explicit permission. Weekly usage must stay below 90%.
11. **2026-11-07: Phase 1 = an SDL3 backend for Vega** (video plus GLES context, keys, virtual gamepad, audio, lifecycle, paths). It unlocks the SDL game ecosystem. The same code develops on macOS with stock SDL3 and ships on Vega. It's an upstreamable open-source contribution, and the N64 libdragon runtime in Phase 2 will sit on it. First title: an SDL-based Doom port with Freedoom (BSD-licensed assets).
12. **2026-11-07: Doom = doomgeneric + Freedoom 2, with music from Chocolate Doom 2.3.0's OPL player and Nuked OPL3**, driven by our SDL3 OPL driver. Authentic DOS FM sound from the WAD's GENMIDI bank, with no MIDI soundfont needed. `apps/doom` is GPL-2.0-or-later. Third-party sources are integrated without edits (build-time staging plus compat shims).
13. **2026-11-07: Licensing (user delegated the choice).** Our code is MIT, © 2026 Mitul Shah. The SDL3 drivers in `engine/sdl3-vega/src` are zlib, matching SDL so they can be upstreamed. `apps/doom` and `apps/quake` are GPL-2.0-or-later because they link GPL engine code. Files carry SPDX headers.
14. **2026-11-07: The arcade is a separate launcher app, and games stay separate packages.** It launches them through the system message router (`vp_launch_uri("pkg://<component>")`), the same path as the home screen, so each game keeps its own icon, lifecycle and memory budget. The alternative, linking all engines into one binary, collides on globals (Doom and Quake both define `Z_Malloc`, for example) and on GPL/MIT boundaries.
15. **2026-11-07: Polling apps detect background/foreground with `SDL_EVENT_WINDOW_HIDDEN/SHOWN`.** SDL3 delivers `DID_ENTER_*` only to event watchers. We kept SDL's semantics rather than patching SDL.
16. **2026-11-07: Quake music from LibreQuake's OGG tracks via `stb_vorbis`** (public domain, pinned), on its own SDL audio stream. The tracks are BSD-3 like LibreQuake's other sounds. The package grows from 27 MB to 55 MB.
17. **2026-11-07: N64 libdragon programs: HLE at the hardware edges, everything else recompiled.** Rules in `n64/recomp/libdragon.hle` stub hardware subsystems (rdpq/rspq/display/joypad/DMA/audio). Host code implements the calls that matter. CPU-side libdragon (assets, DFS, printf, text layout) runs recompiled. This keeps programs authentic while avoiding an RDP/RSP emulator.
18. **2026-11-07: Recompiled memory accesses mask addresses to the 512 MB physical space** (`& 0x1FFFFFFF` in the generated `recomp.h`), backed by an 80 MB lazy reservation. KSEG1 aliases RDRAM, and stray register accesses hit a zero page instead of crashing.
19. **2026-11-07: N64Recomp is patched at build time** (`tools/n64-tools.sh`, idempotent patches; 9 as of 2026-11-14) rather than forked. It is pinned at `598ce20`.
20. **2026-11-14: One public monorepo, `github.com/mitulshah3882/firetv-native` (user asked to publish).** Every app builds on the shared engine (`engine/vegaplat`, `engine/sdl3-vega`, `n64/runtime`) through relative CMake includes, and the case study tells one story. Licenses are already separated per directory (MIT, zlib, GPL), so splitting isn't needed for licensing. The zlib SDL drivers can move to their own repo or upstream to SDL later. The name matches the `com.firetvnative.*` package IDs.
21. **2026-11-14: N64 audio is HLE'd under the mixer API, not at the RSP and not at the player API.** `mixer_*`/`audio_*` are host C (`hle_audio.c`); xm64player, libxm and the wav64 loaders stay recompiled. This keeps the music logic authentic, gives a small, stable interface (one channel struct, one event list), and avoids emulating the RSP mixer microcode (about 1,900 lines with in-mixer VADPCM). Host decoding of VADPCM reuses the game's own `wav64_vadpcm_preload()` for the Huffman layer.
22. **2026-11-14: N64Recomp patch 9: callee-saved registers keep tracked constants across stack restores.** It fixes jump tables whose base address GCC hoisted into s0–s7. The scan is linear, so an epilogue in the middle of a function erased the state. Callee-saved registers are only reloaded in epilogues, so this is safe.
23. **2026-11-14: Launcher icons are 512×512, generated by `tools/make-icons.sh`.** Vega omits sideloaded apps with other icon sizes from "Your Apps & Channels". Each game's icon reuses its arcade card art, in a centred 16:9 band over a blurred fill, so the tile matches the arcade.
24. **2026-11-14: Our SDL drivers stay in this repo; no upstreaming to SDL.** SDL's contributor policy (its `CLAUDE.md`/`AGENTS.md`) says generative AI must not be used for contributions, so the earlier "zlib so it can be upstreamed" plan (#11, #13) is dropped. Using SDL and sdl2-compat as dependencies is unaffected. The drivers stay zlib-licensed.
25. **2026-11-14: SDL2 games run through sdl2-compat with SDL3 linked statically, its symbols renamed.** sdl2-compat normally `dlopen()`s libSDL3. Our SDL3 (with the Vega drivers) is static inside each app, so `engine/sdl2-compat-vega` renames every `SDL_*` symbol in the SDL3 archive to `SDL3V_*` (llvm-objcopy). A preprocessor-generated table (`sdl3v_table.c`) answers sdl2-compat's symbol lookups. Two build-time patches add that loader branch and send startup errors to syslog (stderr isn't in the device log, and the log drops a new process's first seconds, so the message is repeated after 7 s). One package, no shared libraries. Verified with `apps/sdl2-smoke`: SDL2 2.32.74 API, OpenGL ES 2 renderer, 59.9 fps, 48 kHz callback audio.
26. **2026-11-14: Third-party libraries for game ports are built from pinned source inside each app's own Vega build** (`engine/thirdparty/VegaDeps.cmake`): static and position-independent, no sysroot and no package manager. Cross-library `find_package` calls resolve to the in-tree targets. Pins chosen for this toolchain: OpenAL Soft 1.24.3, because 1.25 needs C++20 `std::format`, which this libc++ lacks; glm is forced to C++14 mode, because its `[[nodiscard]]`-after-`__attribute__` order trips this clang.
27. **2026-11-14: vegaplat captures stdout/stderr and presents a black frame as soon as GL is ready.** The device log doesn't capture stdio, and ported games report fatal errors there; SuperTux's "wayland,x11 not available" was invisible until this. Vega kills an app about 20 s after launch if it hasn't presented a frame (AppNotResponding), and SuperTux loads for longer than that before drawing.
28. **2026-11-15: SuperTuxKart's model textures are precompressed to ASTC 6×6 offline** (`apps/supertuxkart/make-assets.sh`), with STK's colouring and alpha masks applied before compression. The Mali-G310 reads ASTC natively, so each texture takes about 1/9 of the GPU memory of STK's RGBA8 and needs no decoding at load. GPU memory in a race fell from over 500 MB (the stick swapped) to about 300 MB.
29. **2026-11-15: STK's per-frame GPU fence wait is skipped on Vega.** STK waits for the previous frame before refilling instance data, which only persistent-mapped buffers need. This driver has none (STK orphans buffers instead), so the wait just serialised CPU and GPU work. Antediluvian Abyss went from about 40 to 53–60 fps.
30. **2026-11-15: SDL's app background/foreground events are sent from Vega's lifecycle thread** (`vp_set_lifecycle_callback`), as SDL does on Android. By the time the game thread sees `VP_EVENT_BACKGROUND` it may already be parked in `vp_gl_swap()`, which is too late to save. Window HIDDEN/SHOWN events stay on the game thread, so #15 still holds for polling loops.
31. **2026-11-15: vegaplat's `glBindFramebuffer` maps framebuffer 0 to the window surface's FBO.** Games written for a default framebuffer (STK, Irrlicht) bind 0 to draw to the screen; on Vega the surface is an FBO. Only names handed out by `vp_gl_get_proc` are wrapped.
32. **2026-11-15: sdl2-compat returns SDL2 keycodes for keys without a character.** SDL3 renumbered the media keys and sdl2-compat passed SDL3's keycodes through, so keycode-based games (Irrlicht's SDL device) saw Play/Pause as an unrelated key. AngelScript (STK's scripting) is built in its portable calling mode on armhf, as STK does on aarch64: its native ARM path assumes soft-float whenever `__ARM_PCS` is defined, which clang defines for hard-float too.
33. **2026-11-15: Games size their window from Vega's canvas, never a hard-coded 1920×1080.** Vega gives apps a logical canvas (`ICanvasConfig`, 1920×1080 on TVs) and scales it to the display, 4K included, so a 4K stick renders the same canvas as the HD one. SuperTux and SuperTuxKart read it through `vp_video_init()`.
34. **2026-11-15: STK performance work is driven by interleaved A/B runs** (`apps/supertuxkart/tools/bench-tracks.sh`, with `tune=` switches per optimisation). Run-to-run noise on the 1 GB stick (swap, memory pressure, heat) is ±3 fps, larger than most single changes.
35. **2026-11-15: STK visits only active track objects** per tick and per frame (decorations do nothing in `update()`), and **writes instance data into a ring of three buffers** per mesh instead of orphaning one every frame. Measured: +15% on Cocoa Temple, +10% on Cornfield Crossing. ThinLTO was tried and dropped: no measurable gain, 3× build time.
36. **2026-11-15: STK's 3D view adapts its resolution** between 0.5 and 0.667 of 1080p (the HUD stays native). It steps down only while the game thread waits on the GPU (`vp_gl_thread_busy()` below 0.88 under 56 fps), keeps a step only if it gains 5%, and remembers the scale per track. CPU-bound tracks stay sharp. 0.75 was tried as the cap and is too much for this GPU. presentBuffer()'s wait was rejected as the signal: GPU work is pipelined, so it stays short even when the GPU is the limit.
37. **2026-11-15: GPU timer queries are not used for profiling on this GPU.** On the Mali-G310 (panthor) a TIME_ELAPSED query around a frame splits the tiler's render passes: SuperTuxKart's frame rate halved while measuring.
38. **2026-11-15: N64brew Jam 2024 minigames are linked statically into one recompiled ELF** (`n64/jam24/`). Each minigame is an `ld -r` object with only its entry points global, compiled `-G 0` (GP-relative relocations to symbols made local by `ld -r` resolve 0x7ff0 off). `--wrap=dlopen/dlsym` answers from a table, and the harness's `core.c`/`minigame.c` link unmodified. `jam_boot.c` replaces the tiny3d menus with a direct boot and a 2D results screen. Each minigame's data is snapshotted at boot and restored on every load, as a fresh DSO would be.
39. **2026-11-15: The rdpq HLE models RDP state and implements only rdpq's leaves on the host** (`n64/runtime/src/hle_rdpq.c`): mode words, combiner, blender, mode stack, scissor and tiles. The command builders (`rdpq_set_mode_*`, the rectangle helpers, header inlines) stay recompiled. Combiner and alpha compare are evaluated per texel into cached textures on SDL_Renderer. A GLES backend is still the plan for 3D.
40. **2026-11-15: Third-party git sources with assets we must not fetch use a pinned sparse, blobless checkout of only the needed paths** (`tools/fetch-deps.sh`, 5th field). Commands that need every blob (`git ls-tree -l`, `grep`, `log -p`) are never run in such a checkout: a blobless clone fetches missing blobs on demand.
41. **2026-11-15: Original games target the measured "lite" neon pipeline** (`docs/research/gpu-bench.md`): RGBA8 or RGB10A2 targets (no FP16: 2.5x per blended layer), glow drawn a second time into a 480×270 target and blurred there, one additive bloom layer, no separate tonemap pass, no framebuffer fetch, point-sprite particles updated in a compute shader (about 32k sustained), at most about 100 draws per frame, and 3 ms of GPU headroom. The textbook HDR + bloom chain + tonemap pipeline measured 47 fps on the same scene.
42. **2026-11-15: GPU benchmarks are timed by wall clock to a `glFinish`,** rendering offscreen with at most two frames in flight, three repetitions after a warm-up, median reported. Validated against the real swap (within 0.1 ms). Every render pass is kept well under one frame: passes of 50 ms or more occasionally stalled the GPU for minutes.
43. **2026-11-15: STK's 3D scale comes from a table measured per track, not a probing controller** (supersedes the stepping rule in #36). Frame rate varies more between parts of one lap than between two scale steps, so the controller from #36 stepped down on slow corners and back up on straights. Each track gets the sharpest step that holds about 60 fps under sustained load, from interleaved A/B runs: 0.5 for eleven tracks, 0.583 for eight, and 0.667 only for Snow Tux Peak and XR591. Most tracks turned out to be GPU-bound at 0.667 (Lighthouse 40 → 51 fps at 0.5). An unknown track (an add-on) starts at the top and only ever steps down, after 3 s under 50 fps while the GPU is the limit.
44. **2026-11-15: STK's `tune=` overrides last one session.** STK saves its config, so a benchmark override used to persist into normal play. The original values go to `vega-tune-restore.txt` and are restored at the next start. Build-time patches that replace STK source use `_vega_stk_replace()`, which fails the build unless exactly one match is found.
45. **2026-11-15: Our GL function pointers have hidden visibility** (`GC_GL_HIDDEN` in `apps/gravity-choir/src/gl.h`). On Vega the dynamic linker binds a default-visibility global named like a GL function (`glClear`) to the driver's function of that name, so `gl_load()` wrote into the driver's read-only code and crashed. Any app that resolves GL by hand and names its pointers after the GL functions needs this.
46. **2026-11-15: Gravity Choir runs SDL3 with GLES 3.0 on the device and desktop GL 3.3 core on the Mac**, from one renderer, using the lite pipeline from #41. Particles and the spring grid run on the CPU rather than in compute shaders: macOS's GL has none, and the Mac preview (scripted runs rendered to PNG) is the iteration loop. All music and sound are synthesized at run time (no samples). Game notes are quantized to the next 16th and taken from the current chord.
47. **2026-11-15: In Gravity Choir, push is a shove, not a wall.** Push is at full strength for 1 s, then fades to 15% over 1.4 s, and flipping the field resets it. A held push was about 5× stronger than an enemy's seeking, so an idle player could not lose (found by a 2-hour unattended run on the TV).
48. **2026-11-15: vegaplat owns audio focus for every app.** It registers the focus listener before requesting focus, maps the changes to a gain (granted 1, ducked 0.25, the rest 0) that ramps over one buffer, keeps the stream running, releases focus in the background and asks again in the foreground. The Appstore's test cases check focus handling, and games never see it.
49. **2026-11-15: The first frame is the package's loading splash** (`assets/image/splash.astc`, ASTC 8×8, 1920×1080, made by `tools/make-splashes.sh`), drawn by vegaplat when the GL context is created. ASTC is decoded by the Mali GPU, so vegaplat needs no image decoder, and each splash is 518 KB. Apps without the file keep the black first frame.
50. **2026-11-15: Remote-friendly changes to jam games are patches applied at build time** (`n64/jam24/patches/<game>.patch`, applied to a copy of the game's source in the build tree). The jam checkout stays as fetched, and a patch that stops applying fails the build.
51. **2026-11-15: The N64 runtime never defines a weak fallback for a recompiled function on ELF.** Under clang, N64Recomp's `RECOMP_FUNC` makes every recompiled function weak, so a weak fallback definition ties with it and the linker keeps whichever comes first (on the device, the fallback). Optional recompiled functions are weak *references* checked for NULL. Mach-O can't link those, so the Mac build keeps a fallback definition.
52. **2026-11-15: Apps are stopped with `vlcm terminate-app --pkg-id <pkg> --force` on the device** (`tools/vega.sh stop`), never `vega device terminate-app`. The CLI matches package ids by prefix: asked to stop SuperTuxKart, it stopped SuperTux.
53. **2026-11-15: Store art for original games is rendered by the game itself.** The Mac build shares the TV build's renderer, and its scripted modes (`keyart`, `play`, `crescendo`) have the demo AI play, so icons and screenshots come straight from the game at 1920×1080. Before submitting, frames captured on a stick confirm they match.
54. **2026-11-15: Our SDL audio driver blocks in `WaitDevice`, never in `PlayDevice`.** SDL calls `PlayDevice` with the device lock held, and the platform write blocks for about a buffer. Blocking there kept the lock held nearly all the time, and SDL's mutex isn't fair, so closing the device from the game thread waited 0.25–6 s (every app's exit froze on its last frame). `PlayDevice` now hands the buffer over and `WaitDevice` writes it. Exits take about 90 ms.
55. **2026-11-15: STK's asset pipeline honours `tRNS` in every PNG mode.** `is_opaque()` only looked for colour-key transparency in palette images, so greyscale and RGB PNGs with a `tRNS` chunk were judged opaque and lost their transparency in conversion. STK's "transparence" blockers (2×2 black PNGs keyed transparent) then drew as black boxes on the overworld, Mines, XR591 and Cocoa Temple. The pipeline also gives the overworld its own copy of `metaldirt_diff.png`, which upstream ships only with Lighthouse.
56. **2026-11-15: Every game ships Vega's system splash** (`assets/raw/SplashScreenImages.zip`: `_loop/loop00000.png` at 1920×1080 plus `desc.txt` with `1920 1080 30` and `c 0 0 _loop`; format from Amazon's `vega_splash_screen_manager.md`). The splash service shows it about 300 ms after launch and stops when the app draws, and vegaplat's first frame draws the same picture, so launch goes straight from the remote press to the game's art. It works for native apps without any API call.
57. **2026-11-16: Gravity Choir's Crescendo is on the remote's Menu button, with Play/Pause as a second key.** Amazon's test criteria say non-media apps shouldn't depend on media keys, so the hints name Menu. Back pauses. A gamepad's Start gets its own button (`GB_START`) and pauses, as players expect, instead of firing the Crescendo.
58. **2026-11-16: vegaplat emits the `fully_drawn` KPI marker** (Vega Tracing Interface, `app` category, a `begin` record named `fully_drawn` with non-empty args), so Amazon's KPI Visualizer and certification runs can measure time to fully drawn. By default it fires at the app's first frame after the splash and again at the first frame after each return to the foreground; an app with a long load calls `vp_fully_drawn_manual()` first and `vp_report_fully_drawn()` when it is usable.
59. **2026-11-16: Jam games' non-redistributable assets are swapped at build time by `n64/jam24/overrides/<game>.mk`**, included after the game's own `.mk`, and `tools/fetch-deps.sh` keeps the original out of the sparse checkout with a `!` pattern. Hydra Harmonics' Superclarendon (commercial) becomes Coustard (OFL) at the same size and outline.
60. **2026-11-16: The rdpq HLE models what TMEM keeps between calls.** A CI sprite's upload or blit loads its palette into the TLUT (games then draw the sprite's pixels as a plain surface with it); `rdpq_tex_upload_sub` keeps the surface's coordinates and wraps within the sub-rectangle; a texture's palette colours are part of its cache key. `rdpq_triangle` draws 2D geometry through `SDL_RenderGeometry` (no perspective or depth: enough for 2D games).
61. **2026-11-16: vegaplat goes quiet after 3 minutes without input.** Vega treats an app playing audio as media playback and holds off the screensaver, so a game left on a title screen with music kept the TV on indefinitely (measured: Gravity Choir stayed in front for 9+ minutes, a silent app got the screensaver at 5). After `kIdleNs` without a key, button or stick move, vegaplat releases audio focus and pauses the stream; the next input, or a return to the foreground, resumes it with a short fade-in. The screensaver's timer starts again when the audio stops, so it shows about 8 minutes after the last input. Back from the screensaver returns to the app, playing again within about 30 ms.
62. **2026-11-16: SuperTuxKart computes LOD distances at level 0 on Black Forest** (`vega_stk_lod_level()`, patched into `LODNode::autoComputeLevel`). Level 0 draws far scenery to 1.0× its base distance instead of the TV preset's 1.42×; models switch level at about the same distance. Interleaved A/B runs at a fixed 0.5 scale: Black Forest 22.7 / 24.4 → 29.9 / 29.4 fps, and 30.0 in a check run. Cornfield Crossing (47.6 / 45.0 → 48.4 / 49.5, then 44.3 in the check run) and Cocoa Temple (no change) gained nothing beyond the noise, so they keep the preset. Screenshots of Black Forest showed no missing scenery. Only the LOD computation changes, never the saved setting, and a lower user setting wins.
63. **2026-11-16: Prism Spire's GPU rules, measured on the HD stick with launch-URI knobs (`?ps=msaa:0,bg:3,comp:0,...`).** These apply to any new 3D game here:
    - MSAA only through `EXT_multisampled_render_to_texture`. It is free in tile memory. A multisampled window surface (`vp_gl_set_samples`) is accepted, but cost about 30 ms a frame.
    - Every full-screen 1080p pass costs about 3.5 ms. Keep them to one copy to the window.
    - Expensive background shading goes in a low-resolution target (1/3 here: 47 → 60 fps).
    - Fragment shaders default to `mediump`, with `highp` for world positions, hashes, screen coordinates and anything thresholded near 1.0. The sun disc turned to noise in fp16.
    - Per-frame vertex data is orphaned with `glBufferData`. Several `glBufferSubData` uploads into one buffer per frame made the driver wait for the GPU mid-frame: 19 ms of CPU wall time at 50% load.
    - The window's framebuffer is read before any of ours is created. The first TV build drew everything into its own FBO and showed black.
64. **2026-11-16: Chroma Orbit draws its sky at 640×360 and only the star's disc at full resolution.** A full-screen pass with per-pixel transcendentals (atan, exp, sin for the corona) cost about 13 ms on the HD stick, even with the nebula cached per world. A/B on the TV (`?co=sky:0,...`): sky off 60 fps, everything else cheap. The sky and corona now render at 640×360 and are upscaled by a plain copy. The star's disc is a small full-resolution quad, so the centrepiece stays sharp: 60 fps.
65. **2026-11-16: Prism Spire composites its background in the final copy, not under the 3D layer.** The 3D pass used to start with a full-screen draw of the low-resolution background into the MSAA target, and the frame then copied that target to the window: two full-screen 1080p passes. Now the 3D pass clears to transparent black and draws only the plinth, the glass, sparks and beams (premultiplied; the additive pass masks alpha writes). The one copy to the window puts the background, its vignette and the menu dimming under that layer. The title screen went from 55–57 fps to 59.2–59.6 on the HD stick; play holds 59.2–59.4 (`?script=play`). In the same pass the background target got 4× MSAA (in tile memory; no measurable cost in play), so the hills no longer stair-step, and the sun's disc became a blend instead of a clipped threshold. A/B knobs: `?ps=bgaa:0`, `?ps=ui:0`.
66. **2026-11-17: tiny3d's RSP commands are caught at libdragon's queue, not at its API (the "rspq tap").** tiny3d writes every command with libdragon's inline `rspq_write`, so there is no function to replace. The runtime aims `rspq_cur_pointer` and `rspq_cur_sentinel` at one 512-byte scratch area in RDRAM (their addresses exported by `tools/n64-recomp.sh`), so every inline write calls `rspq_next_buffer`, which `hle_rspq.c` implements: it decodes the command and resets the pointer. `rspq_overlay_register` reads the ucode's name to recognise `rsp_tiny3d`/`rsp_tinypx`; `rspq_overlay_get_state` stays recompiled. Before this, `rspq_cur_pointer` was NULL and each inline write stored from RDRAM address 0 upward, never reset. Also: code built at `-Os` (tiny3d) calls libdragon's extern-inline `rdpq_mode_*` and colour helpers out of line, so `libdragon.hle` keeps them (they only compute words for leaves we implement); and a game's own `rdpq_*` functions need `keep` rules, as Hydra Harmonics' `audio_*` did. Sword Strike: about 7 tiny3d commands a frame, all ten types decoded with the word counts the design study predicted.
67. **2026-11-18: The N64 runtime draws through its own small GL layer (`n64/runtime/src/gfx_gl.c`), not SDL_Renderer.** 3D needs a depth buffer, shaders and a framebuffer at a multiple of the N64 resolution, which SDL_Renderer doesn't offer. The layer gives the HLE code exactly what it used from SDL, with the same semantics: textured quads with flips, rotation and a colour/alpha modulation, filled rectangles, triangles (textures wrap outside [0, 1], as SDL's geometry does), a scissor, and SDL's three blend modes; the 2D path (combiner baked into textures on the CPU) is unchanged. GLES 3.0 on Vega, GL 3.3 core on the Mac; `N64_SCALE` sets the framebuffer multiple (default 1). **Batching lesson:** uploading each batch's vertices into a freshly allocated buffer took Hydra Harmonics from 60 to 21 fps on the HD stick (hundreds of sprite batches a frame); the layer now records draw segments and uploads the whole frame's vertices once per target, as SDL's renderer does: 60 fps again. **Checked:** screenshot runs are now deterministic (a virtual clock drives both the CPU Count register and `timer_ticks`, and the entropy seed is fixed), so frames were compared pixel by pixel against the old renderer: 8 of 10 within 5/255 (the upscale's rounding); Hydra Harmonics' scaled legend icons differ at a few edge texels, where nearest sampling rounds differently in SDL's software renderer. On the TV: Hydra Harmonics, Land Grab and Brew Volley at 60 fps, the Back hint and exit work. The unit tests draw into the layer's framebuffer in a hidden GL window.
68. **2026-11-18: tiny3d's microcode is modelled on the host (`n64/runtime/src/hle_t3d.c`), with CPU near-plane clipping.** Behind the rspq tap (decision 66), tiny3d's commands run a host model: the matrix stack, CPU transform and directional lighting into a vertex cache addressed by tiny3d's DMEM offsets (from its generated `rsp_tiny3d.h`), triangles, strips and sequences, culling. Triangles go to `hle_rdpq.c`, which draws them in clip space with the current RDP render mode: the colour combiner becomes generated GLSL, plus blender, Z compare/write and alpha compare. Depth is clamped, not clipped (the N64 has no far plane). **Triangles are clipped against the eye plane on the CPU before GL sees them:** on the HD stick, triangles with a vertex behind the eye (w < 0) disappeared, where desktop GL clips them (Sword Strike's walls that run past the camera). Sword Strike runs on the TV with its 3D backdrop at 60 fps.
69. **2026-11-18: 3D depth is clamped per fragment, as on the RDP, not per vertex.** The N64 has no far (or depth) clipping: tiny3d's per-vertex Z is interpolated unclamped and the RDP clamps it per pixel, and where the stored depth is already the maximum any pixel passes. Le Tohu-bohu sets its far plane at 200 with the scene at 165–345, so on the N64 the floor saturates to the maximum and the players drawn after it show. Clamping each vertex's z/w made the floor's interpolated depth come out just below the maximum around them, and the floor hid them. Now `gl_Position` carries no z (nothing is depth-clipped; the CPU clips at the near plane, decision 68), the clip z is a perspective-correct varying, and the fragment shader writes `clamp(z * gl_FragCoord.w)` to `gl_FragDepth`, with `GL_LEQUAL` and a clear to 1.0. Writing the depth costs early-Z, which is negligible at the N64's 320×240 (59–60 fps on the stick).
70. **2026-11-18: HLE scratch memory lives above the 8 MB the program sees.** `n64rt_alloc` used to grow down from the top of RDRAM, right above the program's stack (top − 256 KB). Le Tohu-bohu's stereo music needed a 404 KB VADPCM buffer, which zeroed the stack and crashed. The scratch area now grows down from 32 MB inside the already-reserved address space (untouched pages cost nothing; the program never addresses past 8 MB) and aborts with a message if it ever reaches 8 MB.
71. **2026-11-18: Pyrite64 projects are built by Pyrite64's own editor, on the Mac, against our libdragon and tiny3d.** A Pyrite64 project (Cathode Quest 64 is its `n64/examples/jam25`) is assets plus scene and graph files that the editor converts, with tables and a Makefile it generates, so reimplementing its build isn't worth it. `tools/n64-pyrite64.sh` fetches Pyrite64 at a pinned commit (sparse; its Git LFS files from GitHub's media endpoint, each checked against the SHA-256 in its pointer, by `tools/lfs-fetch.py`), builds the editor once with AppleClang (its `vendored/tiny3d` is linked to our tiny3d pin, the same commit), and runs `pyrite64 --cli --cmd build` on a copy of the project under `build/n64/`. The editor copies its engine into the project from beside its executable, so a copy of it runs from `build/n64/p64-work` with `n64/pyrite64/patches/engine.patch` applied (GCC 16 warnings stop being errors). `N64_INST` points at a staging prefix: our toolchain plus tiny3d's `t3d.mk`.
72. **2026-11-18: The N64 runtime gives each render surface its own GL colour target, and drives the newer VI API.** Pyrite64's swap chain draws into three surfaces and shows them with `vi_show` from its vblank handler, sometimes two frames ahead; with one framebuffer the second overwrote the first before it was shown (a black screen between logo fades). `gfx_gl.c` now has colour-target slots of the screen's size that share one depth buffer (the surfaces share one Z buffer on the N64), `rdpq_attach` draws into the surface's slot and `vi_show` presents it. Interrupts happen when the program waits: `kirq_wait`, `vi_wait_vblank` and every pass of libdragon's `RSP_WAIT_LOOP` run the installed vblank handler; `rdpq_detach_cb`'s callback runs once the frame's commands have. rspq queues are blocks that stay open (`rspq_queue_switch` sets the recording target), and text goes through the command layer so it lands in a queue in order. The runtime reports 8 MB (an Expansion Pak) with the stack at the top, as on the console.
73. **2026-11-18: libdragon's coroutines run on host contexts (`n64/runtime/src/hle_coro.c`).** Pyrite64 runs every node graph (the boot logos, cutscenes, fades) in a `coro_*` coroutine, which libdragon switches with `swapcontext` on the N64 stack. Recompiled code keeps its call chain on the host's C stack too, so each coroutine gets a host stack and a `ucontext` (glibc has `makecontext`/`swapcontext` on Vega's armv7; libSystem on the Mac), its own guest registers and a guest stack from the HLE scratch area. Only one runs at a time, as on the console.
74. **2026-11-18: VADPCM is read from the ROM and Huffman-decoded on the host, not through the program's `wav64_vadpcm_preload`.** The preload `malloc`s the whole file, plus twice that for Huffman: Cathode Quest's music tracks are 3-5 MB, more than its heap. `hle_audio.c` ports the block layout and the Huffman stage (libdragon, MIT) and decodes straight from the ROM; the per-game sound checks in `tools/test.sh` still match the source WAVs. The weak reference decision 51 was about is gone; `tools/test.sh` checks the rule on `n64_sprite_get_palette` instead.
75. **2026-11-18: Recompiled code is compiled with `-fno-strict-aliasing`, everywhere.** N64Recomp's output reads and writes RDRAM through `int16_t*`, `int32_t*`, `uint32_t*` ... casts of the same bytes, which strict aliasing lets the optimizer reorder. Cathode Quest's collision tree builds its free list with halfword stores and copies it with word loads; on the device (armv7, clang 15) the free list came out broken, the pool doubled on every allocation and an assertion stopped the game as the first level loaded, while the Mac build happened to be fine. N64Recomp's own projects build with the flag. Device apps (`N64App.cmake`), `n64/host-run.sh` and `tools/test.sh` all pass it now. Two related device fixes: `tools/n64-recomp.sh` puts an empty statement after every label (N64Recomp declares jump-table addends right after one, which is C23 and clang 15 rejects it), and N64 apps keep unwind tables so a fatal exit logs a host call stack, symbolized on the Mac with `llvm-symbolizer --obj=<app>/build/armv7-release/lib/*.so.debug`.
76. **2026-11-18: Programs that die say how.** `abort`, `die`, newlib's `__assert_func` (a plain C++ `assert`), `std::terminate`, `__cxa_pure_virtual` and libstdc++'s `__throw_*` helpers are HLE functions that log which one ran, the heap break, the program's last 32 `debugf` lines (kept even when `N64_DEBUGF` is off) and the call stack. Before, all of them ended in `_exit` as an unexplained "pause_self".
